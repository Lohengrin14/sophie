# План сайта художника

Дата: 29 октября 2026. Статус: реализован первый локальный билд; подробности запуска и фактические ограничения — в [README проекта](../../README.md). Полный план ниже остаётся целевым объёмом, а не списком уже готовых возможностей.

## Для чего делаем сайт

Посетитель из Instagram должен самостоятельно понять, что можно приобрести, сколько это примерно стоит, как долго ждать и как оставить заявку. Личное общение начинается с уже подготовленных деталей, а художник управляет работами и заявками в админке.

## Уже согласовано с владельцем проекта

| Решение | Следствие для первой версии |
| --- | --- |
| Русский и английский на старте | Переводим интерфейс, контент, формы, ошибки и подтверждения |
| Страна может измениться, покупатели из разных стран | Не привязываем доменную модель к одной стране; провайдеров выбираем перед деплоем |
| Картины — штучный продукт | Наличие, резерв и продажа относятся к конкретной работе |
| Готовые картины продаются через заявку | Сайт сохраняет интерес, художник подтверждает условия лично |
| Индивидуальные заказы обсуждаются лично после предварительной оценки | До запроса контактов показываем доступный ориентир цены и готовности |
| Онлайн-оплата сейчас не нужна | Без эквайринга, криптокошельков, платёжных вебхуков и корзины |
| Имя, псевдоним и контакты через env или админку | Единая конфигурация, env имеет приоритет; незаполненные ссылки скрыты |
| Сначала приложение, потом деплой | Локальная разработка и проверки; хостинг и внешние подключения отдельным этапом |

## Предлагаемые решения

1. **Один проект Next.js + TypeScript + Payload CMS + PostgreSQL.** Витрина, серверные операции и админка в общей кодовой базе.
2. **Админка входит в MVP.** Художник сразу может добавить работу, изменить цену, отметить продажу, прочитать заявку и настроить ориентиры заказов.
3. **Каталог и заказы — два самостоятельных пути.** Отдельно готовая работа с конкретной ценой, отдельно предварительная оценка будущей картины.
4. **Правила оценки задаёт художник.** Сопоставляем сюжет, технику и стандартный размер с диапазоном цены и срока. Произвольные размеры без правила требуют ручного уточнения.
5. **Основа дизайна — спокойная галерея.** Работы занимают главное место; палитра и шрифты централизованы. Конкретный акцент ещё нужно проверить на картинах друга.
6. **Заявки храним в базе.** Мессенджер и почта — каналы общения и уведомлений, но не единственное место учёта.

Подробности и альтернативы — в [архитектуре](ARCHITECTURE.md), последовательность реализации — в [roadmap](ROADMAP.md).

## Что ещё нужно узнать

Эти вопросы не мешают спроектировать и собрать локальное приложение. Они становятся условиями соответствующего этапа.

| Неизвестно | Когда понадобится |
| --- | --- |
| Имя художника, манера работ, фотографии | Для окончательного визуального направления и наполнения |
| Реальные цены, валюта, размеры, техники и допустимые сюжеты | До публикации каталога и расчёта ориентиров |
| Что входит в срок: очередь, работа, просушка; когда заказы закрыты | До включения публичной оценки сроков |
| Кто отвечает, в какие дни и за какое время | Для честного текста о следующем шаге после заявки |
| Контакты, предпочтительный канал, получатель уведомлений | До реального приёма обращений |
| Страна продавца, география хранения данных и отправлений | До деплоя: сервисы, условия продажи и обработки данных |
| Домен, бюджет и человек, ответственный за обслуживание | Перед выбором инфраструктуры |

## Рабочие правила проекта

- Первая версия заканчивается работоспособной связкой «каталог → заявка → админка», а не только красивой главной страницей.
- Сначала мобильный сценарий; затем большие экраны. Проверяем отдельно встроенный браузер Instagram.
- Реальные сроки, цены, отзывы, контакты и произведения не выдумываем. Демонстрационные данные явно помечаем и не публикуем как настоящие.
- Переводы и визуальные токены закладываем с первого компонента.
- Контент и бизнес-правила редактируются в CMS; имя, псевдоним и контакты — через env или CMS с явным приоритетом env. Секреты подключений остаются только на сервере.
- Новые внешние сервисы подключаем, когда нужен конкретный работающий сценарий. В текущем этапе ничего не разворачиваем и не отправляем от имени художника.
