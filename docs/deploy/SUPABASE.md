# Supabase: подготовка базы предпросмотра

Локальная версия продолжает использовать `.env.local` и прежнюю PostgreSQL. Команды `db:preview:*` явно читают отдельный `.env.preview.local` и работают с Supabase.

Google-вход в админку через Supabase Auth настраивается [отдельно](GOOGLE-LOGIN.md).

Пример настроек предпросмотра (реальные значения не коммитить):

```dotenv
DATABASE_TARGET=supabase
SUPABASE_DB_HOST=your-region.pooler.supabase.com
SUPABASE_DB_PORT=5432
SUPABASE_DB_NAME=postgres
SUPABASE_DB_USER=postgres.your-project-reference
SUPABASE_DB_PASSWORD="your database password"
DATABASE_SSL_CA_FILE=.local/prod-ca-2021.crt
PAYLOAD_SECRET=your-separate-preview-signing-secret
```

Пароль хранится без ручного URL-кодирования: `databaseOptions()` кодирует его при сборке строки подключения. Сертификат скачивается из Supabase → Database Settings → SSL Configuration. Проверка сертификата и имени сервера остаётся включённой.

Для облачного окружения вместо пути к файлу можно задать `DATABASE_SSL_CA` с полным PEM-сертификатом. Пул Supabase ограничен тремя соединениями на экземпляр приложения: Payload 3.92 удерживает служебное соединение, ещё нужны соединения для запросов и транзакций, автоматическое изменение схемы и создание базы отключены.

Команды:

```sh
npm run db:preview:check    # только TLS-проверка и число публичных таблиц
npm run db:preview:status   # состояние миграций
npm run db:preview:migrate  # применить ещё не выполненные миграции
```

Миграции находятся в `src/migrations`. Первая создаёт таблицы приложения и историю миграций, вторая добавляет nullable-поля `prefix` и `_objectKey` для облачных файлов. Третья добавляет необязательные цены RUB/USD: прежние суммы в этих валютах переносятся без пересчёта; прежняя цена в EUR сохраняется в старых полях, но не показывается. Старые поля остаются в API для совместимости. Картины, заявки и сотрудники не копируются. Если в непустой базе нет истории Payload, команда предпросмотра останавливается для проверки. Она не предоставляет команды удаления или отката.

Проверка миграций на временной локальной базе:

```sh
npm run test:migrations
```

Она создаёт отдельную базу со случайным именем, применяет миграции дважды, проверяет пустые коллекции и RU/EN, затем удаляет только созданную тестовую базу. Локальная база приложения не мигрируется.

## Постоянное хранение изображений

Созданы два bucket: `artworks` — публичный, `references` — приватный. Они подключаются к коллекциям Payload `media` и `references` через официальный `@payloadcms/storage-s3`.

Дополнительные настройки `.env.preview.local`:

```dotenv
STORAGE_TARGET=supabase
S3_ENDPOINT="https://your-project.storage.supabase.co/storage/v1/s3"
S3_REGION=eu-west-1
S3_ACCESS_KEY_ID="your server access key"
S3_SECRET_ACCESS_KEY="your server secret key"
S3_BUCKET_ARTWORKS=artworks
S3_BUCKET_REFERENCES=references
```

Ключи используются только сервером. Все файлы выдаются через Payload с обычной проверкой прав; приватные референсы не получают публичных или подписанных ссылок. Для облака запись в локальные папки отключена. Локальная версия без `STORAGE_TARGET=supabase` продолжает сохранять файлы локально. Метаданные файлов одинаковы в обеих схемах.

Проверка ключей и видимости bucket (без изменения файлов):

```sh
npm run storage:preview:check
```

## Локальный сайт с облачной базой и фотографиями

```sh
npm run preview:dev
```

- Витрина: http://127.0.0.1:3001/ru
- Админка: http://127.0.0.1:3001/admin
- Отдельный кеш сборки: `.next-preview`.

Это локальный сервер, подключённый к настоящим Supabase БД и Storage, а не публичный деплой. Сотрудники из локальной базы не переносятся: первого администратора предпросмотра нужно создать на этой странице самостоятельно. Доступен только с компьютера, на котором запущен сервер.

С запущенным предпросмотром до создания своего администратора можно выполнить интеграционную проверку подготовки:

```sh
npm run test:storage:preview
```

Проверка временно создаёт QA-сотрудника и два тестовых изображения. Загружает файлы через API админки, проверяет миниатюру, наличие в S3, отсутствие локальных файлов, доступ гостя/администратора и приватность references, затем удаляет только созданные записи и файлы. Картины не создаёт и не переносит.

Следующие этапы: создание своего администратора, добавление новых работ вручную и деплой на Netlify. Перед деплоем отдельно проверить лимиты HTTP-загрузок выбранного хостинга: текущий тест выполнен на локальном сервере с облачным хранением.
