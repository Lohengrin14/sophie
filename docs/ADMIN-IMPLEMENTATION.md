# Новая мастерская · 30 октября 2026

До изменений сохранена вся текущая версия, включая объединённую мозаику: `71f49ec`. Новая работа ведётся в `feat/studio-admin`.

## Структура

Главная `/admin` заменена пользовательским dashboard Payload. Шапка работает и на стандартных экранах сотрудников и ориентиров. Рабочие вкладки — `/admin`, `/admin?tab=artist`, `/admin?tab=requests`; технические редакторы остались по прежним адресам. Вход, сотрудники, auth и существующие API не заменены отдельной системой.

Клиентские формы используют обычную авторизованную сессию Payload и его REST API. Запись каждого блока выполняется отдельным PATCH только соответствующих полей. Для настроек художника используется POST globals. Общая кнопка сохранения всей страницы отсутствует. Есть сообщения об ошибках, загрузке, подтверждение сохранения и защита от ухода с несохранёнными данными.

## Модель галереи

Коллекция по-прежнему `artworks` для совместимости. Существующие записи не переносились и не перезаписывались.

- `image` — прежняя обязательная обложка; продолжает работать для старых записей и публичных ссылок.
- `images` — до десяти upload-связей на `media`, включая обложку. Хук нормализует старые записи при редактировании изображений, убирает дубли, включает обложку и отклоняет переполнение. Одного ограничения интерфейса недостаточно, проверка есть на сервере.
- `displaySize` — необязательное целое 1–5. Старое `null` сохраняет автоматический размер по сантиметрам; ручное значение влияет на мозаичную раскладку.
- `sortOrder` — приоритет, меньшее значение раньше. Сортировка админки и главной едина: `sortOrder,id`. Прежняя отметка `featured` сохранена для совместимости, но не управляет позицией.
- Название обязательно при создании и в пользовательской форме редактирования. Отсутствующее название другой локали не препятствует изменению общих полей. Публикация языковой версии требует непустого названия; описание необязательно. Поля и переводы сохраняются независимо.
- На публичной карточке — обложка и миниатюры остальных изображений. URL не меняется при переименовании.

CMS-значения имени/контактов имеют приоритет над env; пустые значения используют env как резерв. В `.env.local` изменений нет. Структура БД расширена штатным dev schema push Payload; production-миграции остаются задачей этапа деплоя.

## Заявки

Референсы физически остаются в защищённой коллекции `references`, но в пользовательском интерфейсе доступны внутри заявки. Это сохраняет ограничения доступа к файлам и API. Основной экран не позволяет править исходное сообщение или параметры; меняется только статус. Существующие значения статуса сохранены, добавлены `processing` и `shipped`. Снимок оценки представлен читаемыми строками, внутренний токен оценки в интерфейсе не выводится.

## Исправление внешней сетки

При визуальной проверке обнаружено, что после удаления бокового меню Payload оставлял двухколоночный grid. Единственный дочерний элемент с содержимым попадал в первую колонку шириной 0 после гидратации, что сжимало таблицы и формы. Внешний `.template-default` переведён в блочную раскладку; внутренние сетки редактора сохранены. Изменение проверено в авторизованном Chrome: сотрудники, таблица галерей, открытие редактора, художник и заявки отображаются без сжатия, переходы по вкладкам работают. Исходные данные при визуальной проверке не редактировались.

## Следующая итерация мастерской

- Размер на доске отделён от сантиметров: 10 шагов, 1–4×; фиксированный fallback 4. Порядок 1–50, затем размер на доске по убыванию, название и ID.
- Убрана доступность reserved. Локальные старые записи нормализованы отдельным `upgrade-studio.mjs`, без изменения аккаунтов, цен, файлов и сантиметров.
- Добавлено фото художника, пользовательские экраны сотрудников и «Цены и сроки», сортируемые колонки, архив заявок. Изменение статуса требует сохранения и подтверждения; действует предупреждение о несохранённых данных.
- Интерфейс и контент переключаются через общий RU/EN в шапке; штатные инструменты Payload также поддерживают English. Данные посетителя и названия работ не переводятся автоматически.
- Права чтения/изменения проверяются на сервере. Только администратор назначает доступы; новые сотрудники имеют роль staff без доступов. Старые учётные записи без новой роли сохраняют прежние полномочия владельца. Самоудаление и снятие административных прав у себя запрещены. Общие медиафайлы перезаписывает только администратор, редакторы загружают новые и меняют ссылку в своём разделе.
- Проверки: 29 unit-тестов, TypeScript и production build; `test:studio`, `test:smoke`, `test:access`. Временный пользователь с чтением галереи не может сохранять, читать приватные разделы, создавать учётные записи или повысить себе роль.

Повторный визуальный проход через компьютерное управление ограничен: браузерный host недоступен, нативное окно возвращает белый снимок без дерева страницы. Это ограничение проверки, а не подтверждение корректного расположения во всех размерах окна. Требуется ручная проверка владельцем на устройстве перед публичным запуском.
