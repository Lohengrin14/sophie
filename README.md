# Sophie

Сайт художника: каталог готовых картин, заявки на покупку и индивидуальные заказы с ориентиром цены и срока.

Первая локальная версия на Next.js 16, React 19, Payload 3 и PostgreSQL 17. Русский и английский, каталог из CMS, карточки работ, предварительная оценка заказа и формы с сохранением в админку. Онлайн-оплата и деплой отложены.

## Открыть приложение

- Витрина: <http://127.0.0.1:3000/ru>
- Английская версия: <http://127.0.0.1:3000/en>
- Админка: <http://127.0.0.1:3000/admin>

Логин и случайно сгенерированный пароль локального администратора — в `.env.local`, поля `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Файл исключён из Git; пароль в коде или README не хранится. Это локальный администратор, не аккаунт сервиса Payload. Если пользователь уже создан, seed не меняет его пароль.

## Первый запуск

Нужны npm и запущенный Docker. Совместимая Node.js 24.22.2 установлена также как локальная dev-зависимость: команды `npm run` используют её, не меняя системную Node.js.

```sh
npm ci
npm run setup
npm run db:up
npm run seed
npm run dev
```

`setup` создаёт `.env.local` с локальными подключениями и случайными секретами, если файла ещё нет. `seed` создаёт первого администратора, 3 демонстрационные работы и примеры правил оценки; существующие записи не перезаписывает. PostgreSQL хранит данные в именованном Docker volume `sophie_sophie_postgres`, изображения — в игнорируемой папке `media/`. Порт БД 54329 и веб-сервер доступны только на loopback.

Остановить сайт — Ctrl+C в терминале с dev-сервером; БД — `npm run db:stop`. Для повторного запуска достаточно `npm run db:up` и `npm run dev`.

## Тестовые холсты для проверки сетки

`npm run seed:layout` добавляет 10 простых пронумерованных изображений на RU/EN — все пять размеров, обе ориентации и квадрат 120 × 120. Генерирует их программно за несколько секунд, без ИИ и внешних загрузок. Повторный запуск не дублирует записи и не перезаписывает существующие работы. Команда работает только с локальной БД.

Тесты показаны первыми: три на [главной](http://127.0.0.1:3000/ru), все десять в [каталоге](http://127.0.0.1:3000/ru/works). Это отдельный набор для проверки расположения, не настоящие продаваемые картины. [Размеры и инструкция](docs/design/LAYOUT-FIXTURES.md).

## Имя художника и контакты

Два способа: заполнить **«Художник и настройки»** в админке или соответствующие переменные `.env.local`. Значения env имеют приоритет; пустые env позволяют использовать CMS. Отсутствующие ссылки скрываются. После изменения env перезапустите `npm run dev`; после изменения CMS обновите страницу.

```dotenv
NEXT_PUBLIC_ARTIST_NAME=
NEXT_PUBLIC_ARTIST_ALIAS=
NEXT_PUBLIC_ARTIST_INSTAGRAM_URL=
NEXT_PUBLIC_ARTIST_TELEGRAM_URL=
NEXT_PUBLIC_ARTIST_EMAIL=
```

Пока данных нет, используется нейтральное `ATELIER`, без вымышленного имени. Описание художника редактируется на RU/EN в CMS. Публичные ссылки проверяются; секреты подключения не имеют префикса `NEXT_PUBLIC_`.

## Добавить картину

В админке: **Картины → Создать**. Загрузить изображение, указать название и описание, размеры в сантиметрах, технику и обычную цену: например, `650` или `650,50`. Ссылка на страницу создаётся автоматически из названия; при переименовании не меняется. Включить **«Показывать на сайте»** и сохранить. Затем через переключатель языка добавить английское название и описание. До перевода английская карточка скрыта. Менять код или перезапускать сервер для новой картины не нужно.

Кнопки админки переведены на русский; у полей есть подсказки и примеры. Полная короткая инструкция — [как пользоваться мастерской](docs/ADMIN.md). Для разработчика: API и БД по-прежнему хранят цены в минимальных единицах (`65050` = `650,50`), компонент админки выполняет преобразование сам. Существующие цены не пересчитывались.

В **«Ориентиры заказов»** редактируются сочетания сюжета, техники и размера с диапазоном цены и дней до готовности. Нестандартные/неопределённые параметры и неоднозначные правила дают ручное уточнение. В **«Заявки»** видны контакты, пожелания, снимок оценки и приватные изображения. Форма не резервирует картину.

## Проверки

```sh
npm test
npm run typecheck
npm run build
# При запущенном dev-сервере и БД:
npm run test:smoke
```

Smoke-проверка использует только локальный сервер: проверяет RU/EN, вход администратора, запрет гостевого доступа, форму с референсом, снимок оценки и защиту от повторной отправки. Удаляет созданные ею тестовые заявки и файлы. Секреты и токены в вывод не печатает.

## Границы первого билда

Это локальная предварительная версия, а не готовый публичный запуск. В примерах есть изображения ИИ и программно нарисованные тестовые холсты; они помечены как демонстрационные. Размеры, цены и сроки приведены для примера. Внешние уведомления и почтовый адаптер не подключены. Записи действительно сохраняются в локальной БД. Не отправляйте реальные личные данные при знакомстве с интерфейсом.

До production остаются миграции вместо dev schema push, усиление защиты от спама, разграничение ролей сотрудников, очередь уведомлений, согласованные условия/политика, резервные копии, реальный контент и проверка на мобильных устройствах. Сейчас наличие меняется вручную через CMS; связанный атомарный резерв из полного roadmap ещё не реализован.

Сайт использует единые CSS-токены и локальные шрифты; без внешнего CDN шрифтов. RU/EN сейчас реализованы типизированными помощниками и локализованными полями CMS, без next-intl; при расширении словарей можно перейти на запланированную библиотеку. Название Sophie — рабочее название репозитория, не бренд художника.
